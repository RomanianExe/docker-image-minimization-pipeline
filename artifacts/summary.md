Of the 37 configured examples, 25 build from a Dockerfile the example ships and 12 are *prebuilt* — they declare only an `image:`, so `docker compose build` has nothing to build and the baseline is a pull + re-tag instead. All 25 buildable examples were processed end to end; every one of the 6 that stopped at the baseline is a prebuilt entry. See `docs/methodology.md` §12.

## Totals across the processed examples

| Metric | Original | Slim | Change |
|---|---:|---:|---:|
| Image size | 12.14 GB | 4.23 GB | **−65.2%** |
| SBOM components | 12,166 | 4,832 | **−60.3%** |
| Grype findings | 15,255 | 1,930 | **−87.3%** |

Median size reduction is **64.2%** across the 30 examples that had anything to remove; the largest is `nginx-golang-mysql` at 97.7%. Functional tests pass on both the original and the slim image for all 31 processed examples — a slim image that fails its tests is never counted as a result.

**On the vulnerability figure.** Slim removes package metadata along with unused files, so Syft sees less of a minimized image than of the original and part of the drop is reduced detection rather than reduced exposure. Size and component counts are direct measurements; the vulnerability delta is an upper bound. Security decisions should be made on the original image's scan (`docs/methodology.md` §5).
